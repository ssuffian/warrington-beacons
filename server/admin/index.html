What do the match labels mean?

Possible match means the KML point and sheet row probably describe the same place based on name and distance, but no permanent link has been saved.

Sheet row only or KML point only means that item has no credible partner in the other source. That can be intentional for a planned, standalone, or geography-only point.

ID confirmed means the sources share a permanent ID. Confirm a possible match by putting its KML ID in the row’s kmlPlacemarkId cell.

01 / GEOGRAPHY

KML owns the map

Trail shapes and point positions come from the served Google Earth file. Route placemarks carry their location and stable trail group ID in KML metadata. Repeated segments remain separate but share one group ID. This page cannot move, add or delete geometry.

Download served KML Open Google Earth ↗

No shared Earth project link is configured. Download the KML and import it into Google Earth to edit. An updated export must replace the served file; Earth edits do not sync automatically.

02 / CONTENT & INVENTORY

The sheet owns the details

Names, app text, location, beacon programming numbers, hardware status and purchase counts come from the master. Stop Content stores directional wording; KML stores each stop's trail membership and order. Individual points do not need a trail.

03 / PERMANENT LINKS

Link by ID, not by name

Add a kmlPlacemarkId column to Beacons and copy the point’s KML ID from its detail panel. Keep recordKey unique and unchanged when rows move. Alternatively, add recordKey to the KML point’s ExtendedData.

Until that link exists, matching names and nearby coordinates are only suggestions. Duplicate or conflicting IDs are flagged, not silently merged. Confirm the three large position differences before choosing which placemark belongs to each row.

Hardware Minor and Major can change when a beacon is reprogrammed. They are not permanent map identities.

Relink later

The existing site’s admin configuration accepts a public workbook download or a Google Sheets CSV export. A CSV connection refreshes Beacons only; supporting tables stay explicitly labeled snapshots.
